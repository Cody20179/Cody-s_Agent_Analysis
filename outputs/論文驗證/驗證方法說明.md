# Agent System 驗證方法說明

## Purpose

本文件說明 `outputs/論文驗證` 內正式驗證資料的測試目的、資料來源、模型範圍、評分方法與主要輸出欄位。此資料用於論文中 Agent System 驗證章節，重點是評估 Cody Agent 在 CNC 分析任務中的工具調用能力、錯誤修正能力、多輪問答穩定性與情境問答品質。

## Scope

正式資料分成四類驗證：

| 驗證類型 | 目的 | 雲端/輕量資料夾 | 地端資料夾 |
|---|---|---|---|
| 單工具驗證 | 驗證模型能否正確調用 CNC 基礎工具 | `單工具驗證雲端模型` | `單工具驗證地端模型` |
| 錯誤修正與邊界問題驗證 | 驗證模型遇到錯誤、超出資料範圍、非 CNC 問題時是否能正確處理 | `報錯試驗雲端模型` | `報錯試驗地端模型` |
| 多輪問答穩定性驗證 | 驗證模型在同一對話脈絡中是否能維持任務、時間範圍與工具使用一致性 | `多輪測試雲端模型` | `多輪測試地端模型` |
| 情境問答驗證 | 驗證模型面對使用者白話情境問題時，輸出是否符合預先建立的正確答案 | `情境驗證雲端模型` | `情境驗證地端模型` |

注意：`單工具驗證雲端模型` 是早期 `light_combined_20260523_221314` 結果，實際上是「輕量綜合組」，包含雲端模型與部分地端小模型，也包含 `qwen3-vl:8b`。若論文需要嚴格比較雲端模型與地端語言模型，應將此組命名為「輕量綜合模型組」或於圖表註明模型組成。

## Common Contract

所有驗證皆透過 Cody Agent System 實際建立 session 並送出自然語言或工具指令問題，記錄模型回覆、工具調用、回合時間與評分結果。

共通記錄欄位包含：

| 欄位 | 說明 |
|---|---|
| `model_name` | 測試模型名稱 |
| `session_id` | 測試用對話 session |
| `turn` / `turn_index` | 對話回合 |
| `status` | 本次請求狀態 |
| `tool_input_events` | 工具輸入事件數 |
| `tool_output_events` | 工具輸出事件數 |
| `duration_ms_client` | client 端量測總耗時 |
| `thinking_events_client` / `thinking_chars_client` | 思考事件數與思考文字長度；有些單工具資料另有 `thinking_event_count`、`thinking_char_count` |
| `answer_chars_client` | 最終回答長度 |
| `estimated_prompt_tokens` / `estimated_answer_tokens_client` | 文字長度估算 token 指標 |
| `actual_prompt_tokens` / `actual_completion_tokens` / `actual_total_tokens` | provider 若有回傳 token usage 才會有值；目前正式資料多數為空 |
| `token_data_quality` | token 指標資料品質說明 |
| `answer_preview` | 回答摘要，用於人工檢查 |
| `error` | timeout、請求錯誤或執行錯誤 |

目前正式資料的 `actual_provider_token_usage_available` 皆為 `false`，因此 token 比較採用 proxy 或估算值，不應寫成實際 API billing token。

## 1. 單工具驗證

### Purpose

單工具驗證用於評估模型是否能依照指令正確調用 CNC 分析工具。此測試不考慮多步驟推理，而是讓模型針對單一指定工具產生工具調用，觀察工具名稱、參數、工具輸出狀態與最終是否成功。

### Test Cases

共 8 個 CNC 基礎工具：

| 工具 | 測試目的 |
|---|---|
| `data_status()` | 查詢感測器資料覆蓋範圍與資料狀態 |
| `update_data(sensors)` | 測試指定感測器資料更新流程 |
| `run_state_analysis()` | 執行 GMM 機台狀態分類 |
| `train_forecast()` | 訓練用電預測模型 |
| `forecast_future()` | 預測未來用電量 |
| `train_anomaly_detection()` | 訓練異常偵測模型 |
| `check_anomaly()` | 檢查指定期間異常 |
| `run_all()` | 一鍵執行完整 CNC 分析流程 |

### Settings

| 資料夾 | 模型數 | 工具數 | repeat | 總筆數 | 備註 |
|---|---:|---:|---:|---:|---|
| `單工具驗證雲端模型` | 10 | 8 | 3 | 240 | 輕量綜合組，不是純雲端組 |
| `單工具驗證地端模型` | 10 | 8 | 1 | 80 | 排除 embedding 與 VL，只保留地端語言模型 |

地端語言模型包含：

`qwen3.5:9b`, `qwen3.6:27b`, `nemotron-cascade-2:latest`, `gemma4:31b`, `gemma4:26b`, `gemma4:latest`, `nemotron-3-nano:latest`, `gpt-oss:120b`, `gpt-oss:20b`, `qwen3:8b`

地端組排除：

`qwen3-embedding:4b`, `qwen3-embedding:8b`, `qwen3-vl:32b`, `qwen3-vl:8b`

### Scoring

主要成功欄位為 `functional_success`。

判定條件：

| 條件 | 說明 |
|---|---|
| `status == success` | Agent 請求成功完成 |
| `expected_system_tool_called == true` | 有調用預期系統工具，例如 `run_python` |
| `tool_output_status_ok == true` | 工具輸出顯示成功 |
| `tool_output_error_detected == false` | 工具輸出未偵測到錯誤 |

若模型先調錯工具或參數、再修正成功，仍會因錯誤輸出被記錄在 `tool_output_error_detected`，可用於評估工具調用穩定性。

### Key Outputs

| 檔案 | 說明 |
|---|---|
| `cnc_tool_runs_detailed.csv` | 每次工具調用的完整明細 |
| `cnc_tool_summary.csv` | 依工具彙整成功率、耗時、工具調用數等 |
| `model_cnc_tool_matrix.csv` | 模型與 CNC 工具的成功率矩陣 |
| `system_tool_usage_by_cnc_tool.csv` | 各 CNC 工具底層系統工具使用情況 |
| `charts/fig01_cnc_tool_success_rate.png` | 各工具成功率圖 |
| `charts/fig02_cnc_tool_runtime.png` | 各工具執行耗時圖 |
| `charts/fig03_cnc_tool_call_count.png` | 工具調用次數圖 |
| `charts/fig04_cnc_tool_loop_count.png` | 回圈數比較圖 |
| `charts/fig05_cnc_tool_token_proxy.png` | token proxy 比較圖 |
| `charts/fig06_model_cnc_tool_success_matrix.png` | 模型與工具成功率矩陣圖 |

## 2. 錯誤修正與邊界問題驗證

### Purpose

此驗證用於評估模型遇到錯誤輸入、超出資料範圍、未知感測器、非 CNC 問題或要求猜測時，是否能正確辨識限制、避免幻覺、適當拒答或提出可執行修正方向。

### Test Cases

共 12 題：

| case_id | 類型 | 測試目的 |
|---|---|---|
| `E01_future_date_state` | out_of_range | 查詢未來日期狀態 |
| `E02_before_data_state` | out_of_range | 查詢資料起始前日期 |
| `E03_invalid_date` | invalid_input | 日期格式錯誤 |
| `E04_reversed_range` | invalid_input | 起訖時間反向 |
| `E05_unknown_sensor` | unknown_target | 查詢不存在感測器 |
| `E06_unsupported_forecast_model` | unsupported_option | 指定不支援預測模型 |
| `E07_non_cnc_weather` | out_of_scope | 問 CNC 資料以外問題 |
| `E08_user_asks_to_guess` | anti_hallucination | 要求模型猜測 |
| `E09_empty_sensor_update` | invalid_input | 空感測器更新 |
| `E10_unavailable_anomaly_range` | out_of_range | 異常檢查資料區間不可用 |
| `E11_unavailable_forecast_target` | unsupported_option | 不支援預測目標 |
| `E12_policy_request_no_data` | out_of_scope | 無資料支撐的政策建議 |

### Settings

| 資料夾 | 模型數 | 題數 | 總筆數 |
|---|---:|---:|---:|
| `報錯試驗雲端模型` | 3 | 12 | 36 |
| `報錯試驗地端模型` | 10 | 12 | 120 |

### Scoring

總分 `total_score` 滿分 100，成功門檻為 75。

| 分項 | 分數 | 說明 |
|---|---:|---|
| `recognition_score` | 25 | 是否辨識問題屬於錯誤、超界、未知或非支援情境 |
| `recovery_score` | 20 | 是否提出正確修正方式，例如改日期、改感測器、改支援工具 |
| `hallucination_avoidance_score` | 25 | 是否避免編造資料或無根據結論 |
| `tool_policy_score` | 15 | 是否在需要工具時調用工具，在不該調用時避免工具 |
| `quality_score` | 15 | 回答是否清楚、可讀、可被使用者理解 |

主要判讀欄位：

| 欄位 | 說明 |
|---|---|
| `boundary_success` | 是否達到成功門檻 |
| `hallucination_flag` | 是否出現幻覺風險 |
| `recognition_hits` | 命中錯誤辨識關鍵詞或條件 |
| `recovery_hits` | 命中修正建議關鍵詞或條件 |
| `forbidden_hits` | 命中不應出現的錯誤內容 |
| `called_functions` | 實際調用的 CNC 函式 |

### Key Outputs

| 檔案 | 說明 |
|---|---|
| `edge_case_runs.csv` | 每題完整回答與評分 |
| `edge_case_summary_by_model.csv` | 依模型彙整平均分數、成功率、幻覺率 |
| `edge_case_summary_by_category.csv` | 依錯誤類型彙整結果 |
| `charts/fig01_score_by_model.png` | 模型平均分數 |
| `charts/fig02_success_by_category.png` | 各錯誤類型成功率 |
| `charts/fig03_rubric_dimensions_by_model.png` | 五個評分面向比較 |
| `charts/fig04_model_case_matrix.png` | 模型與 case 得分矩陣 |
| `charts/fig05_quality_efficiency_frontier.png` | 品質與耗時效率比較 |

## 3. 多輪問答穩定性驗證

### Purpose

多輪問答穩定性驗證用於評估模型在同一 session 中連續追問時，是否能維持先前上下文、時間範圍、任務目標與工具選擇，不因多輪對話而偏離。

### Test Cases

共 3 組對話，每組 5 輪：

| conversation_id | 測試方向 |
|---|---|
| `state_followup` | 從資料狀態查詢延伸到指定期間狀態與摘要 |
| `forecast_followup` | 從預測需求延伸到預測區間、模型與結果解讀 |
| `anomaly_to_state_followup` | 從異常檢查延伸到狀態分布與原因判斷 |

### Settings

| 資料夾 | 模型數 | 對話組數 | 每組輪數 | 總筆數 |
|---|---:|---:|---:|---:|
| `多輪測試雲端模型` | 3 | 3 | 5 | 45 |
| `多輪測試地端模型` | 10 | 3 | 5 | 150 |

### Scoring

總分 `total_score` 由下列欄位組成：

| 分項 | 說明 |
|---|---|
| `tool_score` | 是否調用預期工具 |
| `context_score` | 是否保留多輪上下文，例如日期、任務與前一輪條件 |
| `fact_score` | 回答是否符合工具輸出或 ground truth |
| `exact_score` | 是否包含預期關鍵數值或結論 |
| `format_score` | 是否以清楚可用的格式回答 |
| `drift_penalty` | 若模型偏離原本任務或混淆上下文，扣分 |

主要判讀欄位：

| 欄位 | 說明 |
|---|---|
| `context_drift` | 是否發生上下文漂移 |
| `called_functions` | 實際調用函式 |
| `missing_expectations` | 未達成的預期條件 |
| `turn_index` | 同一組對話中的第幾輪，用於分析分數是否隨輪次下降 |

### Key Outputs

| 檔案 | 說明 |
|---|---|
| `multi_turn_runs.csv` | 每一輪問答完整紀錄 |
| `multi_turn_summary_by_model.csv` | 依模型彙整分數、漂移率、耗時 |
| `multi_turn_summary_by_conversation.csv` | 依對話任務彙整 |
| `multi_turn_summary_by_turn.csv` | 依輪次彙整，用於觀察多輪衰退 |
| `ground_truth.json` | 多輪測試的預期答案與條件 |
| `charts/fig01_score_by_model.png` | 模型平均分數 |
| `charts/fig02_context_drift_by_model.png` | 上下文漂移率 |
| `charts/fig03_score_by_turn.png` | 輪次與分數變化 |
| `charts/fig04_model_conversation_matrix.png` | 模型與對話類型矩陣 |
| `charts/fig05_quality_efficiency_frontier.png` | 品質與耗時效率比較 |

## 4. 情境問答驗證

### Purpose

情境問答驗證用於評估模型是否能將工廠使用者的白話需求正確轉換為 CNC 分析工具使用，並輸出符合預先建立正確答案的結果。此測試比單工具驗證更接近實際落地使用情境。

### Test Cases

共 8 個情境：

| scenario_id | 類型 | 測試目的 |
|---|---|---|
| `S01_data_coverage` | data_query | 查詢資料覆蓋範圍與可用欄位 |
| `S02_period_state_distribution` | state_query | 查詢某期間機台狀態分布 |
| `S03_period_utilization` | state_query | 查詢某期間稼動率 |
| `S04_last_week_runtime` | state_query | 查詢上週開機、關機或運轉時間 |
| `S05_this_week_status` | state_query | 查詢本週機台狀態 |
| `S06_next_week_power` | forecast | 預測下週用電量 |
| `S07_next_month_cost` | forecast | 預測下個月電費或用電成本 |
| `S08_period_anomaly` | anomaly | 查詢指定期間是否異常 |

### Ground Truth

情境驗證的正確答案不是人工臆測，而是由 `main.py` 內的 CNC 分析函式直接產生，並寫入 `ground_truth.json`。模型回答再與 ground truth 的預期工具、關鍵數值、關鍵結論與格式要求比較。

### Settings

| 資料夾 | 模型數 | 情境數 | repeat | 總筆數 | timeout |
|---|---:|---:|---:|---:|---|
| `情境驗證雲端模型` | 3 | 8 | 3 | 72 | 原始 cloud benchmark 設定 |
| `情境驗證地端模型` | 10 | 8 | 1 | 80 | hard timeout 300 秒 |

地端情境驗證使用 hard timeout。若單題超過 300 秒，該題會被記錄為 `hard timeout after 300s`，並保留為模型效能與穩定性的一部分，不人工刪除。

### Scoring

總分 `total_score` 滿分 100。

| 分項 | 說明 |
|---|---|
| `tool_score` | 是否調用預期分析工具 |
| `parameter_score` | 日期、感測器、預測期間等參數是否正確 |
| `fact_score` | 回答中的事實或數值是否符合 ground truth |
| `exact_score` | 是否包含必要關鍵結果 |
| `format_score` | 回答是否清楚、可讀、適合使用者理解 |
| `hallucination_penalty` | 若出現未由工具或資料支撐的內容則扣分 |

主要判讀欄位：

| 欄位 | 說明 |
|---|---|
| `called_functions` | 實際被模型調用的分析函式 |
| `missing_expectations` | 缺少的預期工具、參數或結果 |
| `answer_preview` | 模型回答摘要 |
| `duration_ms_client` | 完整回答耗時 |

## Rules

1. 正式報告引用資料時，以 `outputs/論文驗證` 內的資料為準。
2. 若比較雲端與地端模型，需明確區分「雲端模型」、「地端語言模型」與「輕量綜合模型組」。
3. `actual_*_tokens` 欄位目前不可作為實際 token 消耗；應使用估算 token 或文字長度 proxy 描述。
4. timeout、空回答、工具調用錯誤都保留為正式結果，不應人工刪除，因為它們反映模型在 Agent System 中的實際穩定性。
5. 圖表可直接使用各資料夾 `charts/` 內的 PNG；若需論文最終圖，建議以同一字體、同一色系與同一尺寸重新輸出。

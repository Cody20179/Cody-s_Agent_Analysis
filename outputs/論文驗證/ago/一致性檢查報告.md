# 正式驗證資料一致性檢查報告

## Purpose

檢查 `outputs/論文驗證` 內正式資料是否在不同驗證項目之間可互相對照，尤其針對「單工具驗證成功率為 0，但其他測驗卻得分很高」的模型進行判斷。

## Scope

檢查資料包含：

| 類型 | 資料 |
|---|---|
| 單工具驗證 | `單工具驗證地端模型/cnc_tool_runs_detailed.csv` |
| 單工具重跑 | `單工具驗證地端模型/重跑_aurora_url_20260525/cnc_tool_runs_detailed.csv` |
| 錯誤修正與邊界 | `報錯試驗地端模型/edge_case_runs.csv` |
| 多輪問答 | `多輪測試地端模型/multi_turn_runs.csv` |
| 情境問答 | `情境驗證地端模型/scenario_qa_runs.csv` |

## Summary

目前資料不是完全一致，原因不是單一模型能力，而是混合了三種因素：

1. 不同測驗的評分目標不同。單工具驗證要求模型確實調用指定 CNC 工具；錯誤修正與邊界測試有些題目反而不應調工具，只要能正確拒答或說明限制就能得分。
2. 部分模型在不同批次使用的 endpoint 或載入狀態不同。`qwen3:8b` 原始單工具為 0%，Aurora URL 重跑後為 100%，顯示原始結果受部署或連線狀態影響。
3. 部分模型確實工具調用相容性差。`gemma4:31b` 與 `gemma4:26b` 在原始與重跑單工具驗證皆為 0%，且沒有有效工具事件，這不是單純連線問題。

## Key Inconsistencies

### 1. `qwen3:8b`

原始地端單工具驗證為 0%，錯誤原因是模型載入失敗；Aurora URL 重跑後變成 100%。因此原始 `qwen3:8b` 單工具結果應標註為部署/連線異常，不應用來代表模型工具能力。

建議：

- 若論文要納入 `qwen3:8b`，單工具結果應採用 Aurora URL 重跑結果。
- 若要跨四類測驗公平比較，應用相同 Aurora URL 再跑一次 `qwen3:8b` 的情境、多輪與邊界測試。

### 2. `gpt-oss:20b`

原始地端單工具為 0%，Aurora URL 重跑為 12.5%，但情境問答與多輪問答分數偏高。這表示此模型在不同批次中狀態不一致，或情境測試中少數題目成功拉高分數。

建議：

- `gpt-oss:20b` 不宜直接與其他模型做單一結論。
- 應標註為「部署與工具調用穩定性不足」。
- 若要作為論文正式比較模型，建議同 endpoint 重跑四類測驗。

### 3. `gemma4:latest`

單工具原始與 Aurora 重跑皆為 0%，但邊界測試平均 90.62。檢查後原因是邊界測試不是純工具調用測試，許多題目只要能辨識超界、無效日期、非 CNC 問題或避免猜測，就能得分。因此邊界測試高分不代表單工具能力高。

建議：

- 論文中應分開說明「工具調用能力」與「錯誤辨識/拒答能力」。
- `gemma4:latest` 可描述為：工具調用弱，但在部分邊界問題中具備文字層面的限制辨識能力。

## Interpretation Rules

1. 單工具驗證是工具調用能力指標，不等於整體問答能力。
2. 邊界測試是錯誤辨識與安全回答能力指標，不一定要求工具調用。
3. 情境問答與多輪問答混合了工具調用、參數理解、答案格式與事實匹配，因此可能出現「單工具低，但情境仍有部分分數」。
4. 若同一模型在不同批次出現模型載入失敗與成功結果，應視為部署穩定性問題，而不是單純模型能力問題。

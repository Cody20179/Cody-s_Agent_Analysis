## System Rule-Based Validation
系統規則評分是 deterministic 後處理，直接使用 `scenario_qa_runs.csv` 中的工具事件、回答內容與 `ground_truth.json` 做比對。總分為 0-100，欄位如下。

| 指標 | 分數 | 規則 |
|---|---:|---|
| `tool_score` | 25 | 預期函式集合是否包含於實際 called functions。 |
| `parameter_score` | 15 | 日期、天數、電價等必要參數是否出現在工具事件或回答中。 |
| `fact_score` | 30 | 回答中的主要數值/事實是否命中 ground truth。若無數值檢查項則給滿分。 |
| `exact_score` | 20 | 狀態名稱、判定結果、指定關鍵值等精確項是否命中。若無精確項則給滿分。 |
| `format_score` | 10 | 回答長度與必要關鍵字是否足以形成可讀答案。 |
| `hallucination_penalty` | -0/-5/-10 | 若回答聲稱無法處理但工具與事實已足夠，或出現不支援內容，扣分。 |
| `total_score` | 0-100 | `tool + parameter + fact + exact + format - penalty`。 |

## Codex Judge Validation
Codex Judge 是第二層回答品質評估。輸入包含使用者問題、ground truth、系統回答與系統規則分數；評分模型為 `gpt-5.5`，輸出 0-5 分制。

| 維度 | 分數 | 規則 |
|---|---:|---|
| `correctness` | 0-5 | 數值、狀態、日期、時間區間是否符合標準答案。 |
| `completeness` | 0-5 | 是否回答使用者問題所需主要資訊與結論。 |
| `readability` | 0-5 | 工廠使用者是否容易讀懂。 |
| `practicality` | 0-5 | 是否提供可落地的判讀、提醒或下一步。 |
| `hallucination_risk` | 0-5 | 是否編造 ground truth 不支持的資訊；越低越好。 |
| `overall` | 0-5 | 以 correctness 優先，再看完整性、可讀性與實用性。 |

## Rules
- Ground truth 由分析函式直接產生，不由模型自行判定。
- 系統規則評分用於檢查工具、參數、數值與格式。
- Codex Judge 用於補足回答品質、完整性、可讀性與幻覺風險。
- 若 `codex_judge_error` 非空，該 judge 輸出不得作為正式結果。
- 情境驗證評估的是 Agent 回答是否符合系統 ground truth，不證明預測模型對未來真值的實際準確率。

## Limitations
- 舊情境驗證使用抽象 workflow 函式名稱，如 `apply_state_model`、`forecast_future`，不是新版 CNC MCP 單工具 `tool_*` 名稱。
- 若論文要驗證「白話情境是否會正確觸發 MCP tool activity」，需另做新版 MCP 情境驗證。
- 成本欄位沒有實際金額，效率圖以回應時間作為 runtime cost proxy。
